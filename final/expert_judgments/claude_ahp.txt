Reasons

LH: An AIS that uses up a sensor node’s memory, CPU or battery can’t be deployed at all, so cost decides whether any of the other features matter.
ST: IoT traffic is repetitive and high-volume, so even a small false-positive rate floods operators with alerts or cuts off legitimate devices.
AD: IoT attacks keep changing, such as new Mirai variants and protocol abuse, so a fixed detector set goes stale quickly.
DS: A central detection server is a single point of failure and a bottleneck, and spreading detection across nodes is closer to how a biological immune system works.
SL: Automatic detector updates matter because many IoT deployments have no operator watching them, but it overlaps with adaptivity and costs extra computation on the device.
DEF: An automated response is useful, but on constrained nodes it is often left to a gateway or edge layer, and a wrong action caused by a false positive can do harm.
RES: Self-healing is worth having, but it is the hardest property to run on cheap devices, and many IoT nodes can simply be reset or reflashed instead.
